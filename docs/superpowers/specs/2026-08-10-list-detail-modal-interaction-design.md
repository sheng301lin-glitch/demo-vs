# 列表详情弹窗交互设计

## 目标

简化任务创建后的操作路径，并统一任务列表与内容列表的详情查看方式：创建成功后直接进入任务队列，任务和内容详情均通过居中弹窗展示，不再使用独立执行页或右侧详情栏。

## 交互流程

### 创建任务

1. 用户在新建任务页提交表单。
2. 创建成功后跳转到 `/tasks?task=<task_id>`。
3. 任务队列页面加载后自动打开该任务的详情弹窗。
4. 用户关闭弹窗后停留在任务队列，可继续筛选或查看其他任务。

### 查看任务详情

- 点击任务表格任意数据行，URL 更新为 `/tasks?task=<task_id>`，并打开居中弹窗。
- 点击关闭按钮、遮罩层或按 `Escape` 关闭弹窗，同时移除 URL 中的 `task` 参数。
- 弹窗展示任务名称、状态、任务 ID、平台、优先级、等待时长、模型、Token、预计费用、执行进度、最近事件和任务操作。
- 取消、重试和优先级修改继续使用现有权限判断与接口。
- 任务处于运行状态时，详情继续按照现有频率自动刷新。

### 查看内容详情

- 点击内容表格任意数据行，URL 更新为 `/content?group=<content_group_id>`，并打开居中弹窗。
- 关闭方式与任务弹窗一致。
- 弹窗展示内容基本信息、结构化内容预览、评分维度、历史版本和优化操作。
- 当正文是 JSON 字符串时，解析并分别展示标题、正文、标签和摘要；解析失败时按普通正文展示，不能阻断详情弹窗。
- 归档和优化继续复用现有接口与状态限制。

## 路由兼容

- `/tasks/:taskId` 重定向为 `/tasks?task=:taskId`。
- `/content/:groupId` 重定向为 `/content?group=:groupId`。
- 重定向使用替换历史记录，避免浏览器返回时再次进入兼容路由。
- 列表筛选、分页与详情参数共存；打开或关闭详情时保留其他查询参数。

## 组件设计

新增一个通用 `DetailModal` 组件，负责：

- 遮罩层、居中容器和标题栏；
- 关闭按钮、遮罩点击和 `Escape` 键关闭；
- 打开时锁定页面背景滚动；
- `role="dialog"`、`aria-modal="true"` 和标题关联；
- 桌面端最大高度与内部滚动，移动端接近全屏展示。

任务详情和内容详情只复用弹窗壳层，各自保留业务查询、展示和操作逻辑，避免创建不必要的通用详情抽象。

## 布局与视觉

- 列表区改为单列全宽，不再为右侧面板预留 380px。
- 任务详情弹窗桌面端宽度约 760px；内容详情弹窗约 900px。
- 弹窗最大高度为视口高度减去安全边距，内容区独立滚动，标题栏和底部操作区保持清晰可见。
- 遮罩使用低透明度深色背景，弹窗保持现有白色卡片、圆角、阴影和紫色主色体系。
- 小于 760px 时弹窗占据大部分屏幕宽高，信息字段改为单列，操作按钮允许换行。

## 状态与数据流

- `TasksPage` 从 `useSearchParams` 读取 `task`，作为详情查询的唯一选中状态。
- `ContentListPage` 从 `useSearchParams` 读取 `group`，作为详情查询的唯一选中状态。
- 点击行只更新对应查询参数；关闭弹窗只删除对应参数。
- 查询参数存在时启用详情请求，不存在时不发请求。
- 加载、失败和空数据状态均在弹窗内部呈现，不改变列表布局。

## 错误处理

- 创建成功但任务列表暂未返回新任务时，仍可通过任务详情接口直接加载弹窗。
- 任务或内容详情请求失败时，弹窗显示失败状态和关闭入口，底层列表保持可用。
- JSON 内容解析失败时回退为原始正文文本。
- 操作按钮继续使用请求中的 pending 状态，防止重复提交。

## 测试与验收

- 创建任务成功后导航到 `/tasks?task=<task_id>`。
- 点击任务行打开带无障碍语义的居中弹窗；关闭按钮、遮罩和 `Escape` 均可关闭。
- 点击内容行打开内容弹窗，结构化 JSON 正文以可读字段展示。
- `/tasks/:taskId` 与 `/content/:groupId` 能正确重定向并打开弹窗。
- 弹窗打开后任务和内容列表保持全宽，不出现右侧预留区域。
- 现有筛选、分页、任务操作、内容归档与优化行为不回归。
- TypeScript 构建、Vitest 测试和浏览器桌面/移动端检查全部通过。

## 范围限制

- 不修改后端接口和数据结构。
- 不重构独立详情页中的其他业务逻辑；旧页面路由仅作为兼容入口。
- 不引入新的 UI 组件库或状态管理依赖。
